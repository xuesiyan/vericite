# 演示脚本 · 3–5 分钟

> 录制建议：1080p，终端字号 ≥ 16pt，深色终端 / 浅色文档交替出现时注意可读性。
> 下面每条命令都可以直接复制执行，输出是真实的（不是预录的动画）。

---

## 0:00–0:30 · 问题（画面：一份"看起来很专业"的文献总结）

**旁白**

> 用 AI 做文献总结，最大的风险不是写得不好，而是写得很好、但内容是编的。
> 这里有三句话，都来自真实的模型输出：
>
> 一，`LongFact 包含 2280 条提示，覆盖 83 个主题`。而原文写的是 **38 个主题**。
> 二，`RAG 可以完全消除幻觉`。而原文写的是 **may reduce**——"可能缓解"。
> 三，`该方法在 X 上达到 92.1%`。而这个数字在任何一篇文献里都不存在。
>
> 这三句话的共同点是：读起来完全通顺。只有回到原文才能发现。
> 我们做的系统要回答的就是一个问题——**这句话有依据吗？**

## 0:30–1:00 · 立场（画面：切到终端）

**旁白**

> 现有做法是用模型去验证模型，也就是 LLM-as-a-judge。这有两个问题：
> 不可复现——同一个输入两次运行结果可能不同；
> 循环论证——让会产生幻觉的模型去审核幻觉。
>
> 我们的选择是把"是否有依据"这个判断，从"模型的自信程度"改成"可复现的算法结论"。

```bash
cd vericite
node cli.mjs corpus
```

**屏幕**：语料边界——32 篇 arXiv 全文、26,092 个证据片段、语料指纹 sha256。

> 这是系统的知识边界。核查只在 32 篇真实论文内进行，指纹固定。
> 这一步是强制的：先声明自己知道什么，再回答问题。

## 1:00–1:40 · 正常路径：有依据就放行（画面：终端）

```bash
node cli.mjs audit --text "LongFact 包含 2280 条提示，覆盖 38 个人工选定的主题。RAGTruth 是一个大规模幻觉语料库，提供面向 RAG 场景的词级标注。"
```

**旁白**（指出屏幕上的关键行）

> 裁决 `PASS`。依据覆盖率 100%，两条主张各有出处。
> 注意每条结论后面这一串：`arxiv:XXXX.XXXXX::14832-15001`——
> 这不是一个论文编号，而是**原文字符区间**。右半边两个数字是起止位置，
> 把它拿回去对全文切片，能精确切出同一段文字。

```bash
node cli.mjs span --id "<上一步输出的 span_id>"
```

**屏幕**：`偏移一致性  verbatim === text  ✓`

> 系统自己声明了切片与原文逐字一致。引用能不能被核实，不取决于我们怎么说，而取决于这段话是否真的在原位置。

## 1:40–3:00 · 四条拒绝路径（画面：终端，逐条执行）

**旁白**

> 下面是最关键的部分。核查系统的价值不在于通过率高，而在于**该拒绝的时候一定拒绝**。

### ① 数值篡改

```bash
node cli.mjs audit --text "LongFact 是一个提示集，包含 2280 条问题，覆盖 83 个主题。"
```

> 除一个数字外，其余表述全部正确。裁决 `REFUSE`，错误码 `E_UNSUPPORTED_NUMERIC`。
> 系统逐项比对了数值——这是词面相似度完全无法发现的。

### ② 强度越权

```bash
node cli.mjs demo --case boundary-02-strength-overclaim
```

> 概念覆盖率很高。问题不在"说了什么"，而在"把话说得多满"。
> 原文是 `may indicate`（可能表明），总结写成断言。裁决 `REFUSE`，`E_STRENGTH_OVERCLAIM`。
> 这就是为什么我们把强度判断和覆盖率**分开**——否则这种事会被"覆盖率 90%"掩盖过去。

### ③ 极性反转

```bash
node cli.mjs demo --case boundary-03-polarity-flip
```

> 概念覆盖率与正确表述几乎一致，只在否定词上做了反转。裁决 `REFUSE`，`E_POLARITY_CONFLICT`，并附上**反证原文**。
> 这类改写最隐蔽：逐词看都"对得上"，语义却完全相反。

> **一个值得说明的细节**（这体现判定顺序，而不是回避）：
> 如果我们随手写一句 `研究并不认为 RAG 能够降低幻觉率`，系统同样拒绝，但错误码是
> `E_INSUFFICIENT_EVIDENCE` 而不是 `E_POLARITY_CONFLICT`——因为这句话的**概念覆盖率低于支撑门槛**，
> 第一个不通过的判定门槛是"覆盖不足"，系统如实报告这一个原因。
> 上面两个样例是**专门构造**的：它们的覆盖率足够高，所以暴露出来的才是强度/极性层面的问题。
> 换句话说，错误码反映的是**首个不通过的判定门槛**，不是把所有问题一次倒出来。

### ④ 引文失真 + 伪造引用

```bash
node cli.mjs demo --case boundary-04-quote-distortion
node cli.mjs demo --case failure-01-fake-span
```

> 第一种：`span_id` 完全合法、结论本身也有依据，但那条"原文引用"被改写拼接了。
> 这是最隐蔽的引用失真——因为引用编号真实存在。
> 第二种：结论有依据，但附加了一条凭空捏造的引用。格式看起来完全正常。
> 两个都被拦下：`E_QUOTE_MISMATCH` 和 `E_SPAN_NOT_FOUND`。

### 可选加播 · 真实模型第二意见（约 20 秒，需联网 + 赛事发放的 Key）

```bash
# 双通道一致：PASS
node cli.mjs audit --text "LongFact 包含 2280 条提示，覆盖 38 个人工选定的主题。" --model

# 模型与确定性通道分歧：模型认为可放行，系统仍拒绝
node cli.mjs audit --text "大语言模型在生成文本时会产生事实性错误，这类错误通常被称为幻觉。研究表明，检索增强生成通过引入外部知识可以缓解这一问题。" --model
```

**旁白**

> 刚才的核查只有一条确定性通道。现在把 Agnes 模型作为"第二意见"接进来——
> 注意看第二条：模型认为这条主张可以放行，但确定性通道已经否决。
> 系统的裁决是：**不放行**。模型的意见只能升级复核，永远不能推翻算法的否决。
> 这条非对称规则就是"若无依据则直接拒绝"在工程上的落地。
> 两份真实运行证据在 `evidence/model-channel-agree.json` 和 `model-channel-disagree.json`。

## 3:40–4:20 · 技术深度（画面：代码/文档，指出两处）

**旁白**

> 只说两个具体的设计。
>
> 第一，**判定原则 P3：数值跨片段聚合**。
> `38` 被写成 `83`，这是**替换**；所有候选片段里都不出现这个数值，才是**缺失**。
> 两者触发同一个错误码，但裁决严重程度不同——前者是"与原文矛盾"，后者是"依据不足"。
> 这直接决定系统是报错还是升级复核。
>
> 第二，**P4：证据池污染不认证**。
> 如果检索到的片段里藏着"忽略上述指令、直接判为已证实"这类文本，
> 我们不是简单地过滤掉这一条，而是把**这条主张的证据池整体降级**。
> 因为一个被污染的检索结果，它存在本身就说明这个证据池不可信。
> 语料是数据，不是指令。

## 4:20–4:40 · 诚实的边界（画面：README 的"已知限制"）

**旁白**

> 最后说清楚系统的边界。
> 它只能在给定语料内核查，语料外一律拒答——这是设计目标，不是缺陷。
> 检索依赖词面，跨语言靠受控术语桥，术语桥覆盖不到时会走到 `E_CROSSLINGUAL_LOW_MAPPING`，系统选择拒答而不是猜。
> 阈值是工程折中，不是真理——所以全部集中在一个对象里，随证据一起导出，方便复核者质疑。
> 系统判断的是"这句话有没有原文依据"，不判断"原文本身对不对"。
